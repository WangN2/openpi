## 课程中的使用顺序

1. L02-L05 先建立 Python 3.11 项目环境，并通过小模型理解张量、损失、梯度和训练循环。
2. L06-L12 加载 `pi05_libero` 做推理，理解 π0.5 的输入、动作输出、配置、调用链和 flow matching。
3. L13-L16 先阅读 LIBERO Spatial RLDS，再使用完整 LeRobot 数据跑通官方数据链路，并从 `pi05_base` 启动低显存微调。
4. L17-L19 用 `pi05_libero` 作为官方对照，评估自己的微调结果并练习排错。
5. L20-L24 根据真实机器人的相机、关节、夹爪和控制接口，采集对应示范数据，再做真机适配和安全联调。

## 使用约定

运行 OpenPI 前设置：

```bash
export OPENPI_DATA_HOME=/ephstorage/openpi_data/cache/openpi
export HF_LEROBOT_HOME=/ephstorage/openpi_data/lerobot
export HF_DATASETS_CACHE=/home/che.lin/.cache/huggingface/datasets
```

这样 OpenPI 对 `gs://openpi-assets/checkpoints/...` 的请求会命中已经准备好的本地缓存。

也可以在仓库根目录执行 `source learning/环境变量.sh`。Arrow 缓存会将压缩 Parquet 展开；为保留 `/ephstorage` 的 checkpoint 空间，缓存固定在空间更充足的系统盘。

RLDS 数据用于学习原始示范数据结构；完整 LeRobot 数据可被当前 `pi05_libero` 数据加载器直接读取。DROID 没有下载，等确认真实机器人和任务后再决定是否需要。

## 训练配置

- 官方 `pi05_libero` 是全参数微调，官方说明需要 70 GB 以上显存，当前 20 GB MIG 切片不能使用。
- 课程新增 `pi05_libero_low_mem_finetune`，使用 PaliGemma 与 action expert 的 LoRA，关闭 EMA，默认 `batch_size=4`。
- 实测 batch 32 和 8 在第一次反向执行时 OOM；batch 4 完成一次参数更新：loss `0.06416`、梯度范数 `0.8708`、参数范数 `1803.77`。
- 两套 LIBERO 训练配置均复用官方 `pi05_libero` 的同数据集归一化统计，已经成功加载 `state` 和 `actions` 两组统计。

## 评测环境

- 独立环境位于 `/ephstorage/openpi/examples/libero/.venv`，使用 Python 3.8.20；125 个包通过兼容性检查。
- 服务器容器没有暴露可用的 NVIDIA EGL 图形设备，因此仿真画面由 Mesa 软件 EGL 渲染；模型推理仍使用 CUDA。该方式速度较慢，但可以完成无显示器的自动评测。
- 实测已创建 LIBERO Spatial 第一个任务、载入官方初始状态、取得 `256×256` 主视角与腕部图像，并成功执行一步动作。
- 官方 `pi05_libero` 权重端到端推理返回 `(10, 7)` action chunk，输出全部为有限数值；首次权重加载约 26 秒，首次 JAX 编译加推理约 30 秒。
- 评测环境变量、LIBERO 路径和无头渲染设置统一由 `source learning/环境变量.sh` 加载。
